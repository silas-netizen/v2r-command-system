# 사진 일괄 세탁 실행 기록 (2026-09-19)

명령: `.venv/Scripts/python.exe -m v2r "사진 세탁 3장씩"`
설정: 원본 1장당 세탁본 3장(`per_original=3`), 브랜드 필터 없음(전체), 1회 실행 상한 3,000장(`worker.DEFAULT_MAX_NEW`).

## 요약
| 항목 | 값 |
|---|---|
| 원본 파일 | 1,166장 (`images/originals/**`) |
| 서로 다른 원본(sha256) | 1,080건 — 폴더 간 중복 86장은 세탁본을 공유 |
| 만든 세탁본 | 3,240장 = 1,080 × 3 (신규 3,240장) |
| 총 소요 | **45.0초** (1차 38.6초 + 2차 6.4초) |
| 실패 | 0건 |
| 브랜드/폴더 | 5브랜드 · 30폴더 |

## 실행 횟수가 2번인 이유 (재실행 가능 확인)
1차 실행은 안전 상한 3,000장에 닿아 스스로 멈추고 이렇게 보고했다.
> 안전 한도 3000장에 도달해 멈췄습니다. 같은 명령을 다시 실행하면 이어서 채웁니다.

같은 명령을 그대로 다시 실행하니 이미 3장을 채운 원본 1,086건은 건너뛰고(`skipped`) 남은 240장만 6.4초에 만들어 마무리했다. 즉 중간에 끊겨도 **같은 명령을 다시 보내면 이어서 채운다**(덮어쓰기 없음: `make_variants`는 기존 `N.jpg` 다음 번호부터 붙인다).

## 실행 후 `상태` 출력 (사진 재고 부분)
```
사진 재고:
  뉴더미스 원본 179장 / 세탁본 537장 / 미사용 537장 부족 4폴더
  우아덤 원본 29장 / 세탁본 87장 / 미사용 87장
  장으뜸 원본 84장 / 세탁본 252장 / 미사용 252장
  코숨핏 원본 179장 / 세탁본 537장 / 미사용 537장 부족 13폴더
  팥순이 원본 695장 / 세탁본 2085장 / 미사용 2085장
```
"부족 N폴더"는 미사용 세탁본이 30장 미만인 폴더 수다(기준 `stock.DEFAULT_THRESHOLD`). 원본이 1~6장뿐인 작은 토큰 폴더들이라 `stock.top_up`으로 원본당 +2장씩 보충하거나, 그 폴더의 사진 자체를 늘려야 한다.

## 규칙 0 확인
세탁본은 모두 `warehouse/images/washed/<원본 sha256>/<번호>.jpg`에 있고, 발행은 `store.pick_variant`를 통해서만 사진을 고른다. 이 함수는 `images/washed/` 밖 경로를 절대 돌려주지 않는다. 회귀 테스트: `tests/test_photo_stock.py::test_picked_photo_is_always_under_washed`.
