# 통검 1등 "카페 글" 형식 참고 — 구현·실측 보고 (2026-09-23 갱신, 16:23 작성)

> **정정 이력**:
> 1. 처음엔 "카페>블로그>포스트>지식iN 순으로 첫 일반 글"을 1등 글로 잡았다. 사용자가 "참고할 1위 글은 **카페 글만**"으로 정정해 카페 전용으로 다시 만들었다.
> 2. 카페 전용으로 바꾼 직후 실측에서 "카페 중 순번"이 15개 전부 2로 나오는 버그를 발견·수정했다(원인·수정 내용은 아래 "카페 이름 배지 오탐" 절). 이 문서는 그 수정을 반영한 **세 번째** 갱신본이다.

## 무엇을 만들었나

`v2r/content/top_reference.py`. 흐름:

1. `resolve_search_query`(자동완성 정규화) → `fetch_integrated_search_dom`(헤드리스, 끝까지 스크롤)로 네이버 통합검색 최종 DOM을 받는다.
2. 광고·쇼핑·뉴스를 빼고 **카페 글(`cafe.naver.com`)만** 대상으로, 화면 등장 순서상 **첫 번째 카페 글**을 1위로 잡는다. `config/bulk.yaml`의 `top_reference.sources`(기본 `["cafe"]`)로 소스를 넓힐 수 있게 만들었다 — `_pick_top_link(dom_html, sources=[...])`.
3. 카페 글이 통검 첫 페이지에 없으면 `{"error": "카페 글 없음"}`으로 캐시한다(성공 캐시와 같은 파일 자리, TTL만 1일).
4. 고른 카페 글을 `m.cafe.naver.com` 주소로 다시 열어(`#cafe_main` iframe 안 본문) 텍스트를 뽑고, 제목 유형·글자수·단락 수·도입 방식·전개 순서·마무리 유형·사진 수·목록/소제목 사용 여부를 계산한다.
5. `format_brief`가 300~400자 한국어 요약으로 압축한다. 문장은 한 줄도 인용하지 않고, 마지막 줄에 항상 `※ 형식만 참고. 문장·표현·사례는 절대 베끼지 말고 우리 브랜드 가이드 논리로 새로 쓴다.`를 붙인다.
6. `reference_for(rt, brand, keyword)`가 검색량 조건(브랜드 pool 상위 50% 또는 검색량 100 이상)을 만족할 때만 brief를 돌려준다. 캐시는 `data/top_reference/<키워드>.json`(TTL 7일, 실패는 1일).
7. brief는 `brand_writer.build_body_prompt`/`build_combined_prompt`의 **user 프롬프트에만** `【참고 형식(통검 1등 글)】` 블록으로 붙는다 — 브랜드 공용 system(프롬프트 캐시 대상)은 손대지 않는다.
8. `bulk_generate.generate_for_brand`가 각 키워드마다 `reference_for`를 부르고, `stats["reference_used"]`/`stats["reference_url"]`을 원고 JSON에 남긴다.

### 캐시 스키마 버전(구버전 무효화)

캐시 내용이 바뀔 때마다 `_save_cache`가 `"version"` 필드를 올리고 `_load_cache`는 버전이 다르면(또는 없으면) 무효로 본다. 지금은 **버전 3**(카페 전용 전환이 2, "카페 이름 배지" 오탐 수정이 3). 버전이 바뀔 때마다 옛 캐시는 자동 무효화되고, 이번에도 실측 전에 `data/top_reference/*.json`을 지우고 다시 수집했다.

### 순위·순번·교차검증·스크린샷

- `extract_serp(dom_html, max_n)`이 화면 등장 순서대로 결과를 훑어 `serp: [{rank, section, source, title, url, is_ad}]`(저장은 상위 15개)를 만든다. 섹션은 도메인 기반 어림이다(한계는 아래 절 참고).
- 우리가 고른 카페 글의 **세 가지 순번**을 계산해 저장한다:
  - `rank_overall`: 광고 포함 전체 화면 순번(상위 200개까지 넉넉히 훑어서 계산)
  - `rank_organic`: 광고·쇼핑을 뺀 순번
  - `rank_in_source`: **카페 글끼리만** 셌을 때 몇 번째인가
- 교차검증: 같은 검색어를 requests 기반(`fetch_integrated_search_html`, 비로그인·스크롤 없음)으로 한 번 더 조회해 **첫 카페 글**을 뽑고, Playwright(로그인 프로필) 결과와 URL을 비교해 `crosscheck_match`를 남긴다.
- 스크린샷 1건: `data/top_reference/더마팩토리.png`(창 없이 헤드리스 캡처, 1440×1400).

### "카페 이름 배지" 오탐 — 발견·수정 (2026-09-23 재정정)

처음 카페 전용으로 바꾼 뒤 실측했더니 **15개 전부 "카페 중 순번"이 2**로 나왔다. 사용자가 "1위를 골랐다면 정의상 1이어야 한다"고 지적해 원인을 봤다.

**원인**: 통검 DOM에서 카페 결과 한 칸마다 실제 글 링크(`cafe.naver.com/<별칭>/<글번호>`) **바로 앞에** 그 카페 이름만 가리키는 "배지" 링크(`cafe.naver.com/<별칭>`, 글 번호 없음)가 따로 박혀 있다. 옛 `extract_serp`는 도메인만 보고 느슨하게 링크를 셌기 때문에 이 배지 링크를 "카페 결과 1번째"로 잘못 세고, 진짜 첫 글은 자동으로 2번째가 됐다 — 15개 키워드 전부에서 같은 오탐이 기계적으로 일어난 것이다(우연이 아니라 네이버 카페 검색 결과 HTML의 고정된 구조 때문).

**수정**: `extract_serp`를 다시 짜서 카페·블로그·포스트·지식iN은 `_pick_top_link`와 똑같은 **글 번호가 있는 엄격한 패턴**(`_RESULT_LINK_PATTERNS`)으로만 세도록 고쳤다. 배지 링크는 글 번호가 없어 애초에 후보에 들지 않는다. 광고·쇼핑·뉴스는 "글 번호" 개념이 없어 기존 도메인 기반 매칭을 그대로 둔다.

**결과**: 재수집한 15개 전부 `rank_in_source: 1`로 나왔다(아래 표). 회귀 테스트 4개(`test_extract_serp_ignores_cafe_badge_link_before_real_article` 등)를 추가해 고정했다.

**리쥬란 "미확인" 원인도 같이 해결됨**: 이전 버전 보고서에서 순번을 못 찾았던 리쥬란도 같은 원인이었다 — 옛 `extract_serp`가 만든 목록과 `_pick_top_link`가 고른 URL이 서로 다른 매칭 방식(느슨한 도메인 정규식 vs 엄격한 글 번호 정규식)을 썼던 탓에 둘이 어긋날 수 있었다. 지금은 둘 다 같은 엄격한 패턴을 쓰므로 어긋날 이유가 없어졌고, 실제로 리쥬란도 `rank_overall: 32, rank_organic: 2, rank_in_source: 1`로 정상 나온다.

## 실패 사례와 대처

- **"카페 이름 배지" 오탐(가장 큰 결함, 위에서 수정)**: `rank_in_source`가 15개 전부 2로 나온 원인이자 리쥬란의 "미확인"의 원인이기도 했다. `extract_serp`를 카페·블로그·포스트·지식iN에 한해 글 번호가 있는 엄격한 패턴으로 다시 짜서 고쳤다.
- **파워링크 광고 중복 집계**: 광고 한 칸에 썸네일/제목/설명 등 여러 클릭 영역이 있어 URL이 조금씩 다르다. 리다이렉트 토큰 앞 16자로 묶어 광고 1칸을 1건으로 집계한다.
- **`load_recent_openings` 예외**: 원고 생성 실측 중 `warehouse/manuscripts/generated/_top_reference_trial/`에 저장했던 시험용 요약 JSON(`list` 꼴)을 그 함수가 `dict`로 착각해 죽는 실제 버그를 발견했다. `v2r/content/brand_writer.py`의 `load_recent_openings`에 "JSON이 dict가 아니면 건너뛴다" 방어 코드를 추가해 고쳤다.
- **카페 글 없음 사례**: 15개 키워드 전부 카페 글을 찾아 이번 실측에서는 발생하지 않았다. `{"error": "카페 글 없음"}` 캐시·빈 brief 경로는 유닛테스트로 확인했다.

## 한계 (정직하게 적어 둔다)

- SERP 섹션 이름은 도메인 기반 어림이다. 네이버가 화면에 실제로 붙이는 "VIEW"·"인플루언서" 헤딩까지 읽으려면 섹션 컨테이너의 CSS 구조를 구조적으로 파싱해야 하는데, 이번 구현은 정규식 기반이라 거기까지는 안 갔다. 등장 순서(rank)는 정확하다.
- 광고/쇼핑/뉴스는 여전히 느슨한 도메인 매칭이라, 이론상 그쪽에도 비슷한 "배지 링크" 오탐이 있을 수 있다 — 다만 이번 지시 범위는 "카페 중 순번"이라 카페·블로그·포스트·지식iN만 엄격하게 고쳤다.
- 네이버 검색 결과는 조회할 때마다 광고 회전·개인화로 순위가 바뀐다. 같은 키워드를 다시 조회하면 1등 카페 글 자체가 달라질 수 있다(이번 재수집에서 5건 중 3건이 실제로 바뀌었다).
- "카페 중 몇 번째"만 볼 뿐, 그 카페 글이 실제로 좋은 글인지는 안 본다(광고성 카페 홍보 글일 가능성도 있다 — 실제로 열어 본문을 읽어 확인했고 전부 사용자 상담/후기 글이었다).
