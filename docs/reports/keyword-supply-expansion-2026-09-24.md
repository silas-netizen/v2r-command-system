# 키워드 채우기 공급원 확대 — 2026-09-24 19:30 실측

## A. 배경

브랜드별 확정 원고 대상(클로드·GPT 둘 다 0에서 3, 3은 bridge_rationale 있는 것만) 1만 개
달성을 위해 사용자 결정("둘 다 허용. 어떻게든 찾자")에 따라 공급원을 넓혔다.
근거: `docs/reports/keyword-fill-loop-2026-09-24.md` F절, `docs/reports/reply-10k-outlook-2026-09-24.md`.

## B. 구현 내용 (`v2r/knowledge/keyword_fill_loop.py`)

1. **상한 상향**: `DEFAULT_CAP` 50,000 → 200,000.
2. **확정 무관 정리**: 회차 종료 시 클로드·Codex 둘 다 4(무관)인 행을 `purge_confirmed_irrelevant`가
   지우고, `rejected_keywords(keyword_norm, keyword, brand, reason, at)`에 정규화(`normalize_keyword`,
   공백 축약·소문자화) 키로 남긴다. `gather_seeds`가 이 표를 걸러 같은 키워드를 다시 시드로 쓰지
   않는다 — 재수집·재채점 비용 절약.
3. **파생 검색어(신규 출처 "파생")**: 확정 원고 대상(검색량 큰 순) + 정리본을 입력으로 클로드
   (요금제 라우터, `keyword_fill_seed_derived` 목적)가 "네이버에서 실제로 검색할 법한" 파생·연관
   검색어를 생성(`derived_seed_terms`). 정규화 중복 제거 후 네이버 키워드 도구로 검색량 확인 →
   기존 채점·교차검증 파이프라인을 그대로 탄다.
4. **자동완성·연관검색 전체 순환**: 상위 30개 고정 대신 원고 대상 전체를 검색량 순으로 두고
   회차마다 다른 구간을 도는 회전 커서(`rotate_eligible_keywords`, `expand_cursor` 표)를 도입.
5. **출처별 채택률 자동 비중 조절**: `fill_until_target`이 직전 회차 `by_source`의 채택률을
   다음 `run_cycle` 호출에 `adoption_weights`로 넘기고, `weighted_cap`이 경쟁·자동완성·연관검색·
   파생 상한을 0.4배(채택률 0)에서 2.5배(채택률 1.0)까지 선형 조절한다.
6. **GPT 교차검증 적체**: 확인 결과 `keyword_relevance.DEFAULT_BATCH_SIZE`가 이미 50이고,
   `run_cycle`이 신규분을 매 회차 바로 `crosscheck_brand`로 넘겨 브랜드별 병렬 프로세스
   (`scripts/rescore-hidden.vbs`) 큐와 동일 경로를 타고 있어 별도 변경이 필요 없었다.
