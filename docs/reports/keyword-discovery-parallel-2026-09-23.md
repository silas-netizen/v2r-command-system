2026-09-23 01:39:36 KST(`date` 확인 시각 01:40:28). 모든 브랜드가 08:20 마감을

## 0. 요약

  브랜드별 복제 프로필의 기존 쿠키만 썼다.
- 원본 `data/browser-profile-naver`는 건드리지 않았다(복제 전 백업만 갱신).
- 실행 중 두 가지 문제를 실측으로 만나 그 자리에서 고쳤다(2절): (1) "전체
  다운로드" 클릭이 헤드리스에서 브라우저를 통째로 닫히게 하는 버그, (2) 코드
  리팩터링 중 실수로 지운 `acct` 변수(`NameError`). 최종적으로는 **다운로드를
  아예 쓰지 않고 조회 XHR JSON 응답을 가로채는 방식**으로 바꿔 문제를 근본적으로
  피했다.
- 사용자 절대 규칙(01:22 지시)에 따라 offscreen(화면 밖 창)도 중단하고
  **완전 헤드리스 + 창 없는 자식 프로세스**(`CREATE_NO_WINDOW`)로 최종
  실행했다 — 실행 중 어떤 터미널·브라우저 창도 화면에 뜨지 않았다(스크린샷
  대신 `Get-Process MainWindowTitle`로 확인, 3절).
- 코드 변경분은 테스트 48개 통과 후 커밋·푸시 예정(6절).

## 2. 문제 원인과 조치

### 2.1 헤드리스 다운로드 브라우저 종료 버그(재확인)

`docs/reports/naver-profile-lock-2026-09-23.md`가 이미 기록한 버그("전체
다운로드" 클릭 직후 헤드리스 Chromium이 통째로 닫힘)가 병렬 실행에서도
그대로 재현됐다(1차: 5개 전부 동시, 3차: 장으뜸만). offscreen(화면 밖 실제
창)에서는 안정적이었지만, 01:22 사용자 지시로 offscreen 자체가 금지되면서
헤드리스에서도 안전한 방법이 필요해졌다.

**조치**: `v2r/knowledge/naver_keyword_tool.py`의 `fetch_related_keywords`를
재작성 — 다운로드 버튼을 아예 클릭하지 않는다:

1. `조회하기`를 누르기 전에 `page.on("response", ...)`를 걸어 응답 바디가
   `{"keywordList": [...]}` 모양(네이버 검색광고 공식 API 필드명)인 JSON
   응답을 가로챈다(정확한 엔드포인트 URL을 몰라도 응답 모양만으로 판정 —
   `_make_response_capture`).
2. 최대 30초(`RESPONSE_CAPTURE_TIMEOUT_SEC`) 기다려도 못 잡으면 결과 표를
   DOM에서 직접 긁는다(기존 `_scrape_table_rows` 재사용).
3. 그래도 안 되면(`use_download_fallback=True`로 켰을 때만) 마지막 수단으로
   다운로드를 시도 — 기본값은 `False`라 실제 실행에서는 절대 다운로드를
   건드리지 않는다.

4차 실행(01:24~01:39)에서는 이 문제가 **한 번도 재현되지 않았다** — 5개
브랜드 모두 끝까지 조회 실패 없이 목표에 도달했다.

### 2.2 `acct` NameError(코드 실수)

관련 없는 리팩터링(브라우저 재기동 로직 추가) 중 `acct = account_id or
"685753"` 줄을 실수로 지웠다. 2차 실행에서 `name 'acct' is not defined`로
드러났고 즉시 복구했다. 회귀 방지로
`tests/test_naver_keyword_tool.py::test_run_for_brand_smoke_no_name_errors`를
추가했다(가짜 브라우저로 `run_for_brand` 전체 경로를 돌려 계정 id가 실제로
쓰였는지 확인).

### 2.3 "브라우저가 닫혔다" 자체 복원력

위 2.1로 근본 원인은 없앴지만, 혹시 모를 재발에 대비해 `run_for_brand`에
자기 브라우저만 재기동하는 경로를 남겨 뒀다: "closed" 계열 오류가 나면
그 프로세스가 자기 `context`/`playwright`(지역 변수, 다른 프로세스와 공유
안 됨)만 닫고 같은 프로필로 다시 열어 이어간다(최대 3회). 이번 4차 실행에는
발동하지 않았다.

## 3. 창 없음 확인

01:22 이후 실행은 `subprocess.Popen(..., creationflags=CREATE_NO_WINDOW)`로
자식 프로세스를 띄우고 `headless=True, offscreen=False`만 썼다. 실행 중
`Get-Process | Where-Object {$_.MainWindowTitle -ne ""}`로 확인한 결과 이
작업이 띄운 창은 하나도 없었다(잡힌 유일한 창은 사용자가 이미 보고 있던
무관한 유튜브 탭).
