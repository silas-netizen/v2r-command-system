## 2. 근본 원인 — "사람이 하는 클릭"을 흉내 내서 쓰기 때문
구글 시트를 **API 없이 헤드리스 브라우저로 사람처럼 조작**(이름 상자에 주소 입력 → 붙여넣기 → 우클릭 메뉴로 행 삽입·삭제)해서 씁니다. 이 방식은 (1) 모달·포커스·지연 하나로 엉뚱한 셀에 들어가고, (2) "행 삽입/삭제"는 되돌릴 수 없는 구조 변경이라 한 번 어긋나면 수천 행이 밀리며, (3) 러너 6개 + 반영 작업 + 정리 스크립트가 **같은 시트를 여러 브라우저 세션으로 동시에** 건드립니다. 가드를 아무리 덧대도 이 세 가지가 남는 한 사고는 반복됩니다.

## 3. 근본 해결책 — 3단계

### A. 즉시 (오늘, 사용자 조치 불필요)
1. **행 삽입·삭제를 자동 경로에서 전면 금지.** 새 키워드는 "마지막 행 아래 붙여넣기"만, 비대상·중복은 삭제하지 않고 G열 "제외" 표기(정리는 별도 점검 절차에서만).
2. **쓰기 단일화**: 시트 쓰기는 한 프로세스(실행기 별도 줄)만 하고, 러너·반영·정리는 그 큐에 요청만 넣음. 브라우저 세션 동시 접근 0.
3. **DB가 원본, 시트는 사본**: 붙인 뒤 export로 행 수·A1·키워드 집합을 검증하고 어긋나면 즉시 중단·알림·자동 복구(백업에서 차이만 재작성).
4. 오늘 사고 복구는 스크립트로 진행 중(빈 행·중복·비대상 정리, A1 복구, 보호 키워드 보존).

### B. 근본 (사용자 1회 조치, 10분) — **Apps Script 웹앱**
- 사용자 구글 계정으로 시트에 **Apps Script를 한 번 배포**(제가 코드를 드리고, 사용자는 "배포" 버튼과 권한 승인만). 그 뒤부터 우리 시스템은 브라우저 조작 없이 **HTTP 요청 한 줄로** "키워드 추가 / 키워드로 행 찾아 G·J·K·L 갱신 / 행 삭제"를 시트 쪽에서 **원자적으로** 처리합니다. 셀 주소 오입력·행 밀림·동시 접근 문제가 원천적으로 사라집니다. 비용 0원.
- 이미 로그인된 구글 프로필(Claude/Make 전용)이 있다면 제가 배포까지 헤드리스로 시도할 수 있으나, 계정 설정 변경이라 **허락을 받고** 진행합니다.

### C. 대안(B가 싫다면)
- 시트 쓰기 자체를 하루 4회 "전체 재작성"(DB에서 완전한 표를 만들어 A2에 통째로 덮어쓰기 + 뒤쪽 잔여 행만 삭제)으로 단순화. 부분 갱신·삽입이 없어 어긋날 자리가 거의 없지만, 러너의 실시간 반영은 4회로 줄어듭니다.

**권장: A는 지금 바로, B를 허락해 주시면 오늘 안에 전환.** "B 진행"이라고 답 주시면 Apps Script 코드와 배포 절차(또는 제가 대신 시도)를 바로 진행합니다.
