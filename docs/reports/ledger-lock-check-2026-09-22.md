## 2. 요금제 잠금 알림 — 오탐이 맞습니다

[docs/reports/alerts/plan-lock-2026-09-22-0300.md](file:///D:/v2r%20%EC%9E%90%EB%8F%99%ED%99%94/v2r-command-system/docs/reports/alerts/plan-lock-2026-09-22-0300.md)

### (a) 잠금 파일은 누가 썼고 왜 없나
- 잠금 파일을 쓰는 곳은 코드 통틀어 **한 자리**입니다 — `LLMRouter.lock_plan()`.
  실행기·사이드카·일꾼 스크립트 모두 같은 `data/plan_lock.json` 을 보므로 **공유는 이미 되고 있었습니다.**
- 알림 파일은 잠금 파일을 **먼저 쓴 다음에만** 만들어집니다. 알림이 저장소 안
  `docs/reports/alerts/` 에 생겼다는 것은, 잠금 파일도 저장소의 `data/plan_lock.json` 에
  분명히 만들어졌다는 뜻입니다(두 경로가 같은 `data_dir` 에서 나옵니다).
- 그런데 지금 그 파일은 저장소 어디에도 없고, **코드에는 이 파일을 지우는 곳이 단 한 군데도 없습니다.**
  03:15:55에 v3 원고 생성이 시작돼 요금제 길로 전부 성공한 것을 보면,
  그 사이에 **원고 생성을 맡았던 일꾼 프로세스가 잠금 파일을 손으로 지우고 다시 돌린 것**으로 봅니다.
  (일꾼의 기록은 남아 있지 않아 이 부분만 정황 추정입니다.)
- 조치: 이제 잠금 파일에 **누가 썼는지(pid)** 를 적고, 로그와 알림에 **잠금 파일의 전체 경로**를
  같이 남깁니다. 다음에 같은 일이 생기면 바로 추적됩니다.

### (b) 진짜 한도였나, 일시 오류였나 → **일시 오류**

| 시각 | 일어난 일 |
|---|---|
| 03:00:28 | claude 오류 원문 `Claude usage limit reached. Please try again later.` → 5시간 잠금(08:00:28까지) |
| 03:15:55 | v3 원고 생성 시작 |
| 03:16:36 ~ 03:20 | 요금제 길 호출 6건 **전부 정상 성공** |

진짜 5시간 한도였다면 15분 만에 풀릴 수 없습니다. **한 번 뜬 오류 문구 하나로 5시간을 잠근 것**이
문제의 본질입니다. 게다가 한도 판정 문구 목록이 너무 헐거웠습니다 — `"limit"`, `"rate"`,
`"try again"` 같은 조각이 들어 있어 **한도와 무관한 흔한 일시 오류 한 줄로도** 잠겼고,
응답이 늦어 시간 초과가 나도 "한도"로 취급했습니다.

### (c) 그 시간대에 돈이 나갔나 → **안 나갔습니다 (0원)**

| 확인처 | 결과 |
|---|---|
| 사용량 장부 02:00~03:30 | `backend=api` 는 전부 시험 오염 줄, 실제 호출 0건 |
| v3 원고 6건 JSON | 6건 모두 `"backend": "plan"`, `"cost_usd": 0.0` |
| `data/v2r.sqlite` events 02:00~03:30 | 관련 기록 없음(03:10 네이버 세션 점검 3줄뿐) |

### 고친 것
1. **1회 실패로는 안 잠급니다** — 한도 문구를 보면 **30초 쉬고 딱 한 번 더** 불러 봅니다.
   두 번째가 성공하면 요금제 길을 그대로 쓰고 잠그지 않습니다. 두 번째도 한도일 때만 5시간 잠급니다.
   (`PLAN_LIMIT_RETRY_SECONDS = 30`, [v2r/llm/router.py](file:///D:/v2r%20%EC%9E%90%EB%8F%99%ED%99%94/v2r-command-system/v2r/llm/router.py))
2. **요금제 세션 점검(실행기)도 같은 규칙** — 점검 한 번 실패로 잠그지 않고 30초 뒤 다시 확인합니다
   ([v2r/engine/worker.py](file:///D:/v2r%20%EC%9E%90%EB%8F%99%ED%99%94/v2r-command-system/v2r/engine/worker.py)).
3. **한도 판정 문구를 좁혔습니다** — `"limit"`, `"rate"`, `"try again"` 삭제.
   이제 `usage limit` / `rate limit` / `limit reached` / `quota` / `too many requests` /
   `overloaded` / `사용 한도` 처럼 한도를 가리키는 문구만 인정합니다
   ([v2r/llm/plan_backend.py](file:///D:/v2r%20%EC%9E%90%EB%8F%99%ED%99%94/v2r-command-system/v2r/llm/plan_backend.py)).
4. **시간 초과는 한도가 아닙니다** — 응답이 늦으면 그 호출만 다음 길로 넘기고, 잠그지 않습니다.
5. **알림 파일에 오류 원문을 싣습니다** — 1차 시도 원문과 잠금을 부른 2차 시도 원문을
   각각 그대로, 잠금 파일 경로와 pid까지 함께 적습니다.

새 시험 4건을 붙여 되살이를 막았습니다: 두 번 실패해야 잠근다 / 한 번뿐인 한도 문구는 안 잠근다 /
흔한 일시 오류 문구는 한도로 안 읽는다 / 시간 초과는 한도가 아니다.
