# 토큰 절약 + 속도 유지 계획 (2026-09-22 02:20 KST, 실측)

## 먼저 정정
- 앞 보고서의 "호출당 3.6만~6.1만"은 **원고 1건(호출 2~3회) 합계**였습니다. 호출 1회 입력은 약 **1.8만~2만 토큰**, 출력 약 5천.
- 맞습니다. 요금제라 돈은 0원이지만 **요금제 한도(5시간·주간)를 갉아먹는 건 토큰 그대로**입니다. 한도가 차면 API(유료)로 넘어가므로 절약이 곧 돈입니다.

## 왜 캐시가 0이었나
원고 1건에 시스템 프롬프트가 **3종류**(본문용·댓글용·부분재시도용)라 서로 달라서, 매 호출마다 지침 전문(2.5만~3만 글자)을 새로 읽었습니다. 캐시는 "앞부분이 똑같을 때"만 걸립니다.

## 절약 6가지 (예상 효과)
| # | 조치 | 입력 절감 | 속도 |
|---|---|---|---|
| 1 | **브랜드당 시스템 프롬프트 1개로 통일**(본문·댓글·재시도가 같은 앞부분 공유, 할 일은 user 쪽으로) → 2·3번째 호출은 캐시 읽기(비용 1/10) | 원고당 약 55% | 더 빠름(캐시 읽기는 처리 짧음) |
| 2 | **같은 브랜드끼리 묶어 5분 안에 연속 생성**(캐시 유효 5분) → 2번째 원고부터 지침을 다시 안 읽음 | 묶음 생성 시 추가 30~40% | 같음 |
| 3 | **지침 정리본 압축**: 코드가 이미 검사하는 규칙(줄 나눔·글자 수·{키워드} 위치 등)은 프롬프트에서 빼고, 중복 문장 제거. 목표 30~40% 축소, 품질 검증은 골든·검증기가 그대로 담당 | 호출당 30% | 빠름 |
| 4 | 시트 예시는 3개까지만(현재 전부) | 호출당 5~10% | 빠름 |
| 5 | 재시도 줄이기: 검증 실패가 잦은 항목(웃음 표기·자리표시자)은 이미 코드 삽입/규칙화. 실패율 기록해 반복되는 건 프롬프트 한 줄로 고정 | 호출 수 −20% | 빠름 |
| 6 | **사용량 장부**: 호출마다 캐시 읽기/생성 토큰을 기록해 일일 보고에 "절약률" 표시(증명용) | — | — |
