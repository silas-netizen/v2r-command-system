### 1) 클로드 1차 채점

`warehouse/guides/정리본/<브랜드>.md`에서 브랜드/제품/타깃/핵심 논리를 300자로 뽑아
(`brand_summary`) system 프롬프트에 넣고, 키워드 100개씩 user 프롬프트로 넣어
`LLMRouter`(요금제 길, 0원)로 `relevance(0~3)` + `rationale`을 JSON 배열로 받는다
(`build_system_prompt`/`build_user_prompt`/`parse_response`).

판단 기준을 프롬프트에 명시했다(사용자 지시 반영): **병원 진료과·지역명·일반 생활어는
브랜드 논리로 이어지는 당위성이 억지스러우면 무조건 3**, 직접 연결 근거가 뚜렷할 때만 2 이하.

실패 묶음은 자동 2회 재시도(`score_batch`). 프롬프트 지문(sha256)·사용량은 기존
`llm_usage-*.jsonl` 장부에 그대로 쌓인다(용도=`keyword_relevance`).

### 2) DB 마이그레이션

`keywords` 테이블에 열 추가(`migrate`): `rationale`, `relevance_llm`, `scored_at`,
`primary_brand`, `relevance_codex`, `needs_review`, `codex_checked_at`. 기존 `relevance`
(낱말겹침 값)는 손대지 않는다.

### 3) Codex(GPT) 교차 검증 (사용자 추가 지시, 2026-09-23)

같은 100개 묶음을 **같은 시스템/유저 프롬프트**로 Codex CLI에 한 번 더 태운다
(`score_batch_codex`/`run_codex`): `codex exec --skip-git-repo-check -s read-only
-m gpt-6-astra -c model_reasoning_effort="low" -`. **`gpt-6-astra` 모델이 실제로
동작함을 확인했다** (`codex exec -m gpt-6-astra` 시험 호출 성공, ChatGPT 요금제 안,
비용 0원). 실패 시에만 `gpt-5.6-sol`(low)로 대체.

두 점수를 합쳐(`crosscheck_rows`) 차이가 2 이상이면 `needs_review=1`, 보수적으로
(더 무관 쪽인) 큰 값을 최종 `relevance_llm`으로 채택한다. 브랜드별 ±1 이내 일치율은
`agreement_rate`. 최종 원고 대상(`manuscript_eligible`) = 클로드·Codex **둘 다** 0~2.
