# 일상 글 진도 점검 추가 (2026-09-27)

## 요약(5줄)
1. 새 명령 "일상 글 진도 점검"을 매시 5분(09:05~01:05, 발행 허용 시간 안)에 자동 실행하도록 실행기 내장 예약에 추가했습니다.
2. 이 점검은 오늘 발행 합계·카페별 건수·최근 60분 건수·최신 발행 작업 상태를 보고, 정체(60분 10건 미만)나 실패 방치를 스스로 감지합니다.
3. 문제를 찾으면 슬랙 🔴 경보 + 같은 명령("자사 카페 일상 글 카페별 100건 실제 발행 댓글 랜덤")을 자동으로 다시 큐에 넣습니다(하루 최대 5회, 이미 도는 작업이 있으면 넣지 않음).
4. 매시 `docs/reports/daily-posts-board-<날짜>.md` 현황판을 통째로 다시 써서 항상 "지금 상태 한 장"을 보여주고(카페별 표·완료 예상 시각·오늘 문제와 조치·할 일), 슬랙에도 매시 한 줄(정상 📊 / 문제 🔴)을 보냅니다.
5. 어제 09:55 실패 원인이던 "연속으로 등록할 수 없습니다"(consecutive_limit) 오류를 계정 영구 차단이 아니라 다른 계정으로 즉시 재시도하게 고쳤고, 재시도할 계정이 아예 없을 때도 작업 전체를 실패시키지 않고 5분씩 최대 3번(15분) 기다렸다가 같은 글을 이어서 시도하도록 바꿨습니다.

## 반영 시점
- **명령/예약/현황판/consecutive_limit 처리**: 모두 코드 변경입니다. 사용자 지시대로 지금 실행기(작업 268)를 재시작하지 않았으므로, 오늘 밤 02:30 이후 실행기가 다시 시작될 때부터 적용됩니다.
- **예약표(`config/schedule.yaml`)에 추가한 매시 항목**: `schedule.py`가 매 루프마다 예약표를 다시 읽으므로, 이 부분만은 실행기 재시작 없이도 다음 5분 단위 시각부터 바로 동작합니다. 다만 새 명령(`publish_progress_check`)을 실제로 해석·실행하는 코드 자체는 재시작 전까지 옛 버전이라 "그런 작업을 모릅니다" 식으로 실패할 수 있습니다 — 그래서 이 기능이 실제로 정상 동작하는 시점은 결국 **오늘 밤 02:30 이후**입니다.
- 09:00 정규 회차 중복 방지와는 충돌하지 않습니다. 전날 작업이 아직 running이면 재큐하지 않고(이미 도는 중), 그 작업이 60분간 0건이면 기존 감시(`monitor.py`, 30분 정지 감시)가 먼저 failed 처리 후 자동으로 이어서 실행합니다 — `publish_daily`는 이미 `RESUMABLE_TASKS`에 있어 이 보호가 원래부터 걸려 있었습니다(코드 변경 없이 확인만 함).

## 사용자가 할 일
- 오늘 밤 02:30 이후 실행기가 재시작되면 별도 조치 없이 자동으로 매시 점검이 시작됩니다.
- 슬랙에서 🔴로 시작하는 "일상 글 진도" 메시지가 오면 `docs/reports/daily-posts-board-<날짜>.md` 현황판을 열어 "오늘 문제와 조치"·"사용자가 할 일" 항목을 확인해 주세요. 자동 재큐로 해결되지 않고 "재큐 상한 도달"이 뜨면 그때만 사람이 봐야 합니다.
