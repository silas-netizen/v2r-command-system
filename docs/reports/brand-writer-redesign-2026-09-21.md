# 브랜드 원고 생성기 재설계 (2026-09-21) — 사용자 피드백 반영 설계서

사용자 피드백(원고 피드백.txt) 요지: 글자 수보다 **맥락**이 문제. 대대댓글2의 기존 논리·흐름 유지, 팥순이 댓글2~대대대댓글2 맥락·후기형/질문형 순서 준수, **Make 지침 전부 학습**, 줄 나눔 규칙, 팥순이 가상 멘트("농촌진흥청 25% 검증"·"국가기관 인증"·"바로 구매했어요"·"강추") 필수, 평가서의 개선 제안 5개 적용. 이후 브랜드별 1건씩 테스트.

## 진단(원인)
1. **지침을 앞 3,500자(본문)/2,500자(댓글)만 넣고 있었다** (`brand_writer._guide_excerpt`). 브랜드 지침은 26~33KB라 **90%를 버리고** 있었음 → 대대댓글2 논리·팥순이 흐름·줄 나눔 규칙이 모델에 전달되지 않음. 이것이 맥락 붕괴의 1차 원인.
2. 기존 완성 원고를 예시로 전혀 주지 않음(few-shot 0) → "기존 원고 형태"를 알 길이 없음.
3. 후기형과 질문형이 같은 댓글 프롬프트를 씀.
4. 검증기가 글자 수 위주(맥락·구조 검사 없음).

## 설계 (구현 순서대로)
### A. 지침 전문 학습 (잘라내기 폐지)
- `_guide_excerpt`의 상한을 없애고 **브랜드+유형 지침 전문**을 system의 **캐시 블록**에 넣는다(이미 `system_blocks`+`cache_control` 구현됨). 30KB ≈ 15~20k 토큰, 캐시 읽기 단가라 원고당 비용 미미.
- 지침 파일 선택: `warehouse/guides/★NEW 카페 바이럴★/` 브랜드별 파일. 팥순이는 질문형 `NEW 팥순이 카페 질문형`, 후기형 `UPDATE 팥순이 카페 후기형`. 우아덤은 `우아덤 카페 단순화`(`카페 바이럴 자동화(우아덤)`은 보조).
- 지침에 있는 **줄 나눔 규칙**(모바일 1줄 약 20자, 문단 사이 빈 줄)을 프롬프트 상단에 "형식 절대 규칙"으로 한 번 더 명시.

### B. 기존 완성 원고 few-shot
- `data/brand_sheet_<브랜드>.xlsx`의 `게시글 쓰기 원본` 탭에서 **같은 원고유형**의 완성 행 2~3개(본문 셀: `제목:` … 본문 … 댓글 12개가 sheet_text 형식)를 골라 system 캐시 블록에 "기존 완성 원고 예시(형태·흐름을 그대로 따를 것)"로 넣는다. 선택은 결정적(파일 순서 앞에서부터, 본문 150자 이상·댓글 12개 갖춘 행)이어야 캐시가 유지된다.
- 프롬프트에 "예시의 **문장·소재를 베끼지 말고**, 문단 수·줄 길이·댓글 역할·브랜드 등장 시점·말투만 따라라" 명시.

### C. 대대댓글2 고정 틀 (개선안 1)
- 질문형 대대댓글2 = `{브랜드/제품명} + 대안이 안 되는 이유 한 마디 + "검색해보면 나와요"류 마무리`, 40~60자. 지침 원문의 예문을 프롬프트에 인용.
- 금칙어: "제품보다", "제품 얘기랑은 별개로", "관리법 개념", "프레임", "헷갈리지 마시고", "방법이 중요" → 검증기 **하드 실패**(해당 댓글만 재생성).

### D. 후기형 전용 댓글 프롬프트 (개선안 2)
- 후기형(팥순이 등): 대댓글2 = 작성자가 제품명(`팥순ㅇㅣ` 표기) 언급, 대대댓글2 = 여분 계정 "저도 이거 먹는중", 대대대댓글2 = 작성자 맞장구. 질문형 틀과 **완전히 분리**된 `_REVIEW_COMMENT_*` 프롬프트.
- 검증기 "제품명 최초 언급 위치"는 **실제로 제품명이 처음 나온 라벨**을 찾아 `first_mention_label`과 비교(현재 라벨 문자열만 보는 오판 수정).
- 팥순이 가상 멘트: 후기형·질문형 지침에 적힌 위치대로 `농촌진흥청 25% 검증`, `국가기관 인증`, `바로 구매했어요`, `강추` 중 **지침이 요구하는 것은 필수** → 검증기에서 없으면 해당 댓글 재생성. 위치는 지침 원문을 따르고, 지침이 위치를 안 정하면 댓글2(권위/검증)·대대대댓글2(구매/강추)에 둔다.

### E. 길이 기준 현실화 + 부분 재생성 (개선안 3)
- 기본: 댓글2 ≤90, 대대댓글2 ≤60, 나머지 ≤40. 팥순이: 댓글2·대대댓글2 ≤90, 나머지 ≤50. 본문은 기존 `body_max`.
- 사용자 결정(2026-09-19) 유지: **상한 100% 초과만 실패**(그 이하 경고). 실패 시 그 댓글만 재생성(`build_partial_retry_prompt` 경로).

### F. 본문 형식 검사 (개선안 4)
- (a) 줄 나눔: 본문 각 줄 ≤ 28자(공백 포함; 지침의 "1줄 20자 안팎")를 넘는 줄이 전체의 20% 초과면 실패 → 본문 재생성. (b) `{키워드}`가 규칙의 문단 뒤에 있는지 **문단 인덱스**로 검사. (c) 오프닝 첫 어절이 최근 생성 20편(`warehouse/manuscripts/generated/**`)과 같으면 경고+재생성 1회.

### G. 상투구 회피·근거 주입 (개선안 5)
- 회피 목록(기존 상투구 3종 + 새로 발견 시 추가)을 프롬프트에 넣고, 대대대댓글2·댓글5·대댓글5는 문장 구조를 매번 다르게.
- 댓글4는 본문에서 "작성자가 이미 해 본 방법"을 뽑아 프롬프트에 넘긴다(지적이 본문과 맞게). 댓글5는 수치·기간 필수(검증: 숫자 1개 이상).

### H. 검증기 = 맥락 우선
- 실패(재생성) 항목: 대대댓글2 금칙어/틀, 제품명 최초 언급 위치, 팥순이 필수 멘트, 줄 나눔, `{키워드}` 위치, 댓글5 수치, 길이 100% 초과, 이모지, 본문 브랜드명.
- 경고만: 길이 상한 초과(100% 이내), 오프닝 반복.

### I. 테스트·산출
- 단위 테스트: 지침 전문 포함(길이), few-shot 선택 결정성, 후기형/질문형 프롬프트 분리, 대대댓글2 금칙어 실패, 최초 언급 위치 실제 탐지, 팥순이 필수 멘트, 줄 나눔·문단 인덱스 검사, 길이 기준.
- 실제 생성 테스트는 **브랜드별 1건**(사용자 지시): 우아덤·장으뜸·코숨핏·뉴더미스 질문형 1건씩, 팥순이 질문형 1건 + 후기형 1건 → `docs/reports/brand-test-2026-09-21.md`(기존 원고 예시와 나란히, 검증 결과·비용 포함).

## Make로 돌리는 게 나은가 (판단)
- 일관성: Make 시나리오는 같은 지침을 **전문으로** 모델에 주기 때문에 지금까지는 Make 쪽이 원고 형태가 안정적이었다. 위 A+B(지침 전문 + 기존 원고 예시)를 넣으면 같은 입력 조건이 되고, 여기에 검증·재생성·중복 게이트·이모지 게이트가 붙으므로 **우리 쪽이 더 일관**될 수 있다.
- 비용(원고 1건): 우리 쪽 = Sonnet 캐시 읽기(지침+예시 ≈ 25k 토큰 × $0.30/M ≈ $0.008) + 출력 ≈ 2.5k × $15/M ≈ $0.04 + 재시도 1회 ≈ **$0.06~0.10**, 캐시 쓰기는 5분에 1회($0.09). 25건 ≈ $2~2.5. Make = OpenAI 토큰(비슷하거나 더 큼, 캐시 없음) + Make 작업 수 요금 + 사람이 결과를 옮기는 수고 + 검증 없음.
- 결론: **우리 생성기 유지(A~H 적용)**, Make는 비교 대조용으로만. 단, 브랜드별 1건 테스트에서 기존 원고와 형태가 안 맞으면 그때 Make 병행 재검토.
