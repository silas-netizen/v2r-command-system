# 시트 두 번째 탭 서식 통일 (2026-09-24)

작성 시각: 2026-09-24 00:59 (KST, `date` 실측)

## 지시 요약

브랜드 시트 두 번째 탭("노출 현황")에 새 키워드 행을 추가할 때 텍스트만 붓지 말고, 드롭다운(데이터 확인)·서식이 있는 열은 기존 행의 것을 복사해 서식을 통일하라는 지시. 오늘 추가된 행(우아덤 181·장으뜸 283·뉴더미스 451건)이 드롭다운 없이 텍스트로만 들어가 있던 것을 고친다.

## 구현

- `v2r/sources/sheets_writer.py`에 `copy_row_format(spreadsheet_id, gid, src_row, dst_first, dst_last, n_cols=15)` 추가. 값은 절대 건드리지 않는다(읽지도 쓰지도 않고, "값 붙여넣기" 메뉴는 코드 어디서도 클릭하지 않는다).
- `append_rows`가 값을 쓴 뒤 기본적으로(`copy_format=True`) `copy_row_format(src=2, dst=새로 추가된 행 범위)`를 자동으로 부른다. `sync_keywords_to_sheet`도 내부적으로 `append_rows`를 타므로 앞으로 시트에 키워드가 추가될 때마다 서식이 자동으로 맞춰진다.

## 실측 — 어떤 메뉴/방법이 실제로 먹혔는가

1. 컨텍스트 메뉴 항목의 실제 표기는 "서식만 붙여넣기"가 아니라 **"서식만"(Ctrl+Alt+V)**, **"데이터 확인만"**이었다(긴 문구로 찾으면 못 찾음). `Shift+F10` → `[role=menuitem]:visible`에서 "선택하여 붙여넣기"를 찾아 하위 메뉴를 연 뒤 부분 문자열로 일치시켰다.
2. **`hover()`로는 헤드리스 크로미움에서 flyout 하위 메뉴가 거의 안 열렸다** — 예외 없이 조용히 실패(값은 그대로, 서식·드롭다운만 안 먹음). `click()`으로 바꾸니 하위 메뉴가 열렸다.
3. 그래도 산발적으로(특히 장으뜸 탭) 메뉴 클릭이 반영 안 되는 경우가 있어 `force=True` 클릭 + "메뉴가 실제로 닫혔는지"(`[role=menuitem]:visible` 개수가 상단 메뉴바 수준으로 줄었는지) 확인하는 로직을 추가했다.
4. **결정적 원인**: 브라우저 컨텍스트에 클립보드 권한(`clipboard-read`/`clipboard-write`)을 미리 부여하지 않으면 `Ctrl+C`가 조용히 실패하는 경우가 있었고, 또한 **첫 번째 "서식만" 붙여넣기 뒤 복사 표시("marching ants")가 풀려서 두 번째 "데이터 확인만" 붙여넣기가 빈 클립보드에 대고 실행**되는 경우가 재현됐다(장으뜸 탭에서 여러 차례 실패 후 확인). 두 가지를 다 고쳤다: `new_context(permissions=["clipboard-read","clipboard-write"])`로 권한을 미리 부여하고, "서식만" 붙여넣기 뒤 원본을 **다시 `Ctrl+C`** 한 뒤에 "데이터 확인만"을 붙여넣도록 바꿨다. 이후 4개 브랜드 전부 재현 성공.
5. 드롭다운 확인은 CSV(export)로는 안 되고(서식·데이터 확인 규칙은 CSV에 안 실림), 구글 시트 격자가 캔버스 렌더링이라 셀별 DOM/CSS 클래스로도 확실히 못 잡았다 — 최종적으로는 **스크린샷 기반 육안 확인**(대상 범위 시작/중간/끝 행에서 드롭다운 화살표가 보이는지)으로 검증했다.

## 앞으로 자동 반영

`append_rows`(따라서 `sync_keywords_to_sheet`)가 기본으로 `copy_format=True`라, 앞으로 시트에 새 키워드 행이 더해질 때마다 2행 서식·드롭다운이 자동으로 복사된다. 서식 복사가 실패해도 값 쓰기 자체는 무효화되지 않고 `format_error`로만 남긴다(값 반영이 서식보다 우선).

## 테스트

`tests/test_sheets_writer.py`에 메뉴 텍스트 탐색(`_paste_special`, 가짜 page)·`copy_row_format` 자동 호출(`append_rows`)·비활성화(`copy_format=False`) 테스트를 추가했다. 전체 스위트 24건 중 23건 통과, 1건(`test_sync_keywords_to_sheet_picks_only_target_rows`)은 이 작업과 무관하게 세션 도중 다른 일꾼이 `sync_keywords_to_sheet`의 채택 로직을 `keyword_relevance.is_manuscript_target` 기반으로 다시 짜면서(같은 저장소를 동시에 편집 중) 옛 테스트 기대값과 어긋난 것으로 확인했다(내 변경분과 무관 — `git stash`로 내 파일만 제외하고 재현해도 여전히 실패).
