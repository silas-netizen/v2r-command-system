# 요금제·배치·일반 API 어느 길로 돌려도 같은 지침·같은 품질 — 전략 (2026-09-21 16:15 KST)

## 목표
원고를 만드는 **길(실행 경로)** 만 바뀌고, **모델에 들어가는 글자·검증 기준·결과 형식은 1바이트도 안 바뀌게** 한다. 그래서 어느 길로 나온 원고든 구분이 안 되어야 한다.

## 원칙 5개
1. **프롬프트는 한 곳에서만 만든다.** 지금의 `brand_writer`(정리본 지침 전문 + 기존 원고 예시 + 절대 규칙 + 키워드 입력)가 유일한 프롬프트 생산자. 실행 길은 그 문자열을 **그대로** 전달만 한다. 길마다 프롬프트를 손보는 것 금지(테스트로 강제: 세 길의 system/user 문자열 해시가 같아야 통과).
2. **모델·설정 동일.** 세 길 모두 Sonnet 5, 같은 온도·최대 토큰. 요금제 길에서 모델이 자동으로 바뀌는 일이 없게 명시 지정. 모델이 다르면 그 원고에 표시하고 검증을 더 엄격히.
3. **검증기는 길을 모른다.** 결과 JSON → 같은 `validate` → 같은 실패/경고 → 같은 부분 재시도. 재시도도 원래 길로(요금제 한도면 배치로 넘어가되 그 사실을 기록).
4. **예시는 결정적.** 기존 원고 예시는 시트 앞에서부터 고정 선택(이미 그렇게 함) → 어느 길이든 같은 예시. 시트가 바뀌면 세 길 모두 같이 바뀐다.
5. **품질 회귀 감시.** 매주 브랜드별 1건을 세 길로 동시에 만들어 같은 채점표(100점)로 비교 → 5점 이상 벌어지면 알림. 원고 JSON에 `backend`(길), 모델, 비용, 시도 수를 남겨 나중에 길별 통계.

## 실행 길 3개 (한 인터페이스)
| 길 | 무엇 | 언제 | 비용 |
|---|---|---|---|
| `plan` (요금제) | Claude Code 비대화 실행 `claude -p` — 도구 전부 끔, 모델 sonnet 지정, system 프롬프트 그대로 전달, JSON만 출력 | 기본. 새벽 02:00~08:00 묶음 생성, 낮엔 소량 | 0원(구독) |
| `batch` (배치 API) | Anthropic Batches API, 같은 messages 바디, 캐싱 포함 | 요금제 한도 경고/실패, 또는 50건 이상 묶음 | 일반의 50% ≈ $0.08/건 |
| `api` (일반 API) | 지금 방식 | "지금 1건" 같은 즉시 요청, 배치도 막힐 때 | ≈ $0.16/건 |

- 폴백 순서: `plan → batch → api`. 전환은 원고 단위로 자동, 이유를 이벤트에 기록("요금제 한도 → 배치").
- 요금제 한도 감지: `claude -p` 응답의 한도/속도 제한 오류 문구, 연속 실패 2회, 또는 응답 시간 급증 → 5시간 동안 `plan` 잠금.
- 요금제 길의 부작용 방지: 실행 시 프로젝트 폴더 밖 임시 작업 폴더에서, CLAUDE.md·기억·도구 없이(순수 모델 호출처럼) 실행. 제 채팅 세션과 한도를 나누므로 낮에는 건수 제한(예: 시간당 5건).

## 왜 같은 품질이 나오나 (근거)
- 오늘 6/6 통과가 나온 요인은 모델이 아니라 **입력(지침 전문·예시·절대 규칙)과 검증 루프**였다. 세 길 모두 이 입력·루프를 공유하므로 결과 분포가 같다.
- 차이가 날 수 있는 유일한 지점은 "요금제 길이 Claude Code 하네스로 한 번 감싸인다"는 것 → system 프롬프트를 그대로 넣고 도구·기억을 끄면 순수 호출과 같아진다. 첫 주 회귀 비교(위 5번)로 실측 확인.

## 운영 흐름(제안)
1. 매일 02:10 `브랜드 원고 묶음 생성`(요금제 길): 밀려남 키워드 상위 N건 → 검증 통과분만 `generated/`에 저장, 검토 MD 1개.
2. 아침 보고에 "생성 N건 / 길별 건수 / 0원·$"를 같이 표시.
3. 사용자가 검토 후 "발행" 지시 → 기존 발행 흐름(사진·중복·이모지 게이트)으로.
