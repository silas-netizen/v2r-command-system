# 장애 보고: V2R 로그인 횟수 제한 (2026-09-19 11:16 KST)

## 무슨 일
- V2R API가 `429 RATE_LIMIT_LOGIN` 응답: 기기 지문당 하루 로그인 20회 제한, 약 12시간 뒤(00:10경) 해제.
- 자사 일상 글 발행이 100건 완료 후 11:16부터 전부 실패(75건 실패 이벤트). 작업 59는 제가 중지시킴.
- 원고는 소모되지 않음: 실패 8행은 `failed`로 남아 다음 실행에서 다시 사용됨.

## 원인
1. 토큰 저장 파일(`data/session.json`)이 남아 있질 않았다. 쓰기 자체는 되지만
   (`_store_token` → `_save_file`, 경로도 정상), `ensure_token`이 만료를 전혀 보지 않아
   1시간마다 403 `TOKEN_ERROR`가 났고 그때마다 `V2RClient.request`가 부르는
   `AuthSession.invalidate()`가 **그 파일을 지웠다**. 지운 뒤의 재로그인이 429로 막히면서
   파일이 사라진 채로 남았다 → 뒤에 뜨는 모든 프로세스(실행기·점검 스크립트·테스트)가
   각자 새로 로그인.
2. 토큰 수명 약 1시간 → 만료 때마다 갱신 대신 재로그인.
3. 오늘 브라우저 로그인 실험(지문 시험 3~4회)도 같은 카운트에 포함.

## 대응(진행 중, 코드 수정 일꾼)
- 토큰 1개를 파일로 공유(모든 프로세스 재사용), 만료 5분 전 `refresh_token`으로 갱신, 로그인은 최후 수단.
- 하루 로그인 15회 넘으면 프로그램이 스스로 멈춤(서버 20회 전).
- 429 장기 제한을 받으면 슬롯을 실패 처리하지 않고 해제 시각까지 대기 후 같은 글부터 재개(텔레그램 알림).

## 지금 상태 (12:20 갱신)
- 사용자 승인으로 기기 지문 1회 교체(기존 지문 `data/device.json.bak-20260919` 백업) → 로그인 1회 성공, refresh 갱신 실제 확인(200), 쿠키 24시간. 실행기 재시작·발행 재개.
- 자사 일상 글: 104건 발행 완료 / 목표 250. 해제 후 같은 명령 재전송하면 이어서 진행(발행 기록으로 중복 없음).
- 제휴·사진·원고 생성은 API와 무관(원고 생성은 Anthropic, 사진은 GPT 웹) → 계속 가능.

## 재발 방지 규칙
- 로그인은 실행기만, 스크립트·테스트는 저장 토큰 재사용.
- 로그인 시도 전 로컬 카운터 확인.

## 조치 완료 (코드)
- `v2r/api/auth.py`: 토큰 파일 원자적 저장 + 만료(`exp`) 해독 + `refresh_token` 쿠키/만료 보관,
  `ensure_token`(요청 직전)·`maintain`(serve 30분 주기), 로그인 예산 `data/login_log.json`(15회).
- `v2r/api/client.py`: `RATE_LIMIT_LOGIN` 및 `retry_after > 900초` 429 → `kind="rate_limited_long"` 즉시 예외.
- `v2r/engine/publish.py`·`worker.py`: 레이트 제한이면 슬롯을 태우지 않고 한 번만 알린 뒤
  해제까지 대기(30초 박자, 최대 6시간) → 같은 슬롯 재시도. 발행 행은 재시도 가능한 `failed`로.
- 확인: `python -m v2r session` (토큰·쿠키 만료, 최근 24시간 로그인 횟수).
- 자세한 규칙: `docs/reference/v2r-auth-protocol.md` §7.
