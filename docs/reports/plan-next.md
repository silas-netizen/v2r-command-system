## 다음 단계 (병렬 묶음으로 실행)

### 묶음 A — 코드 마무리 (일꾼, 사용자 입력 불필요)
1. 통합 검증 결과 치명·중요 수정
2. 전체 테스트 → 저장(커밋) → GitHub 푸시
3. 사용 설명서 `docs/USAGE.md` (비개발자용, 명령 예시 위주)

### 묶음 B — 실제 V2R 연결 검증 (순서가 필요한 유일한 부분)
로그인 → 카페·계정·게시판 목록 → 드라이런 → 테스트 카페(태극/소나무) 실제 1건.
- 옛 코드가 못 찾았던 로그인 API를 새로 구현했으므로, **첫 실제 호출에서 가정 12건이 맞는지 확인**해야 함.
- 이미지 붙여넣기(SE-ONE Ctrl+V)도 여기서 처음 실제 테스트.
- 실패하면 스스로 진단 → 못 고치면 보고.

### 묶음 C — 사용자 입력이 필요한 것 (준비되는 대로, 순서 무관)
| 항목 | 필요한 것 | 왜 |
|---|---|---|
| 텔레그램 원격 명령 | 봇 토큰 + 허용할 채팅 ID | 모바일에서 명령·보고 받기 |
| 슬랙 (선택) | 봇 토큰 + 허용 채널 ID | 동일 |
| 모델 사용 | Anthropic API 키 | 일상 글 각색·댓글 생성(선택 기능) |
| 사진 창고 | Drive 이미지 폴더를 zip으로 내려받거나 Drive 데스크톱 동기화 폴더 경로 | 사진 수집기 입력 |
| 원고 시트 | 시트가 "링크 있는 사람 보기" 공개인지 확인 | 로그인 없이 CSV로 읽는 방식 |

### 묶음 D — 운영 준비
- **운영 현황판(HTML)**: 발행 현황(예약·완료·실패·불확실, 카페·계정별, 완료 링크) / 진행 상황(실행 중 작업·대기열·최근 명령) / 점검 상황(끊김 점검 결과·계정 제한·사진/원고 재고). 프로그램 저장소(SQLite)에서 자동 갱신. 카페별 1건 실발행 검증 후 제작.
- 브라우저 자동 로그인(`.env` 계정으로 프로그램이 입력) → 사용자 개입 0
- 실행기 상주(`python -m v2r serve`)를 윈도우 시작 시 자동 실행(작업 스케줄러 등록)
- 끊김 점검(`reconcile`) 하루 1회 자동
- 효율표·보고서 갱신

## 자체 점검: 비효율이었던 것과 고친 방식
1. **V2R 화면 코드(2MB) 분석을 제가 직접 함** → 컨텍스트 소모. 앞으로 이런 분석은 Explore 일꾼에게.
2. **묶음 1~5 검증을 한 일꾼에게 통째로** → 토큰 244k. 앞으로 묶음별 분할 병렬.
3. **통합 일꾼이 인터페이스 불일치 7건 우회** → 설계서에 함수 시그니처를 미리 고정하지 않은 탓. 다음 설계부터 시그니처 포함.
4. **Make 추출을 12개 통째로** → 순차 분할(폴더별) 규칙 추가.
5. **통합 검증을 리뷰 수정 완료 후에 하려던 것** → 읽기 전용이라 충돌 없으므로 지금 즉시 병렬 시작함(위 표).
6. 잘 된 것: 5묶음 병렬 코딩(총 ~45분에 210 테스트), 문서 먼저 → 코딩 순서, 비밀은 `.env`만.
