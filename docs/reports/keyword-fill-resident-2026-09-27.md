# 키워드 채우기 상주화 (2026-09-27)

## 요약

우아덤·장으뜸·코숨핏·뉴더미스가 09-26 채점 적체·시드 고갈 뒤 프로세스가 그대로 종료돼(11:19 수동 재기동) 사람이 다시 띄워야 했던 문제를 고쳤다. 이제 적체·시드 고갈·회차 중 예외 어느 것도 프로세스를 끝내지 않고 스스로 기다렸다 재개한다. 목표(브랜드당 1만 개) 달성·정지 파일·DB 용량 상한 세 가지만 정상 종료다.

## 고친 것 (4줄)

1. 적체(3,000 미만이 될 때까지) 5분마다 재확인 후 자동 재개 — 종료 대신 대기.
2. 시드 고갈이면 30분마다 새 확정 키워드(0에서 2·미사용) 생겼는지 확인 후 자동 재개.
3. 적체 판정 기준을 실제 검증 대상(3=당위성 전부 + 4=무관 상위 30%)만으로 좁힘 — 0에서 2 자동확정분은 적체에서 제외.
4. 회차 중 예외(네이버 도구 차단·DB 잠김·LLM 실패)는 로그 후 10분 대기·재시도, 프로세스 종료 금지.

근본 원인: 기존 코드는 적체를 만나면 대기 없이 바로 다음 회차로 넘어가 `round` 카운터만 급속히 소진했다 — 코숨핏은 실제로 `round=100000`(상한)에서 조용히 끝난 것을 `fill_progress.json`에서 확인했다.

## 20분 실측

재기동 직후부터 20분 뒤까지 5개 브랜드 모두 프로세스가 살아 있었다(재확인 시각 기준 `python.exe` 10개 — 브랜드별 2개 프로세스 정상).

- 갱년기: 2회차에서 적체 7,505건 감지 → 로그에 "300초 뒤 다시 확인" 남기고 대기 상태(`적체대기`)로 전환 — 새 로직이 실제로 작동함을 확인.
- 우아덤·장으뜸·코숨핏·뉴더미스: 정상 수집 중(`running`), 아직 적체·시드고갈 없음.

## 브랜드별 1만 예상 시점

이번 회차 채택률이 매우 낮아(0에서 0.008 수준) 단순 외삽은 부정확하다. 우아덤·코숨핏은 이미 5,000대~7,000대라 하루 이내 가능성이 있고, 뉴더미스·갱년기는 2,000대~3,000대라 며칠 더 걸릴 수 있다. 정확한 시점은 상주 순환이 자동으로 재개·진행하며 `data/keywords/fill_progress.json`에 계속 갱신되므로, 그 파일로 실시간 확인하는 편이 예측보다 정확하다.

## 사용자가 할 일

없음 — 5개 브랜드 모두 새 코드로 재기동해 상주 중이며, 적체·시드고갈·오류 어느 것도 사람이 다시 띄우지 않아도 스스로 재개한다. 정지하려면 `data/keywords/fill_STOP` 파일만 놓으면 된다.
