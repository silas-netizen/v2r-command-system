# 세 업무가 끊기지 않게 하는 근본 설계 (09-27 12:00)

대상: 노출 확인 · 키워드 추가 · 일상 글 매일 작성

## 지금까지 끊긴 이유 (공통)
- 프로세스가 오류 한 번에 죽는다(DB 잠김, 연속 등록 제한, 시드 고갈, 적체 중단).
- 죽은 것을 살리는 감시가 업무마다 따로 있고, 그중 하나(노출 감시)는 파일 손상으로 23시간 멈춰 있어도 아무도 몰랐다.
- 감시를 세션 예약(대화형 크론)에 맡긴 부분이 있었고, 그건 발화하지 않았다.
- 세 업무가 같은 DB 파일을 같이 써서 서로를 멈추게 했다.

## 설계 5층
1. **일 자체가 안 죽게(프로세스 층)** — 노출 작업자·채점 워커·채우기 순환·실행기 모두 "오류 → 기록 → 대기 → 재시도" 상주형. 종료 조건은 오직 정지 파일(data/STOP)과 목표 달성. (채점 워커 완료, 노출 작업자·채우기 순환 오늘 오후 완료)
2. **죽어도 5분 안에 살아나게(감시 층)** — 감시를 **하나**로 통합: 예약 작업 V2R-Supervisor(5분, 숨김)가 실행기·노출 작업자 6·채점 워커 18·채우기 5의 심장박동 파일(60초 갱신)을 보고 7분 이상 멈춘 것만 골라 재기동. 스크립트는 ASCII·CRLF로만 작성하고 자동 검사(테스트)로 손상을 막는다. 감시 자체의 실행 기록도 남겨 "감시가 죽은 것"을 다음 층이 잡는다.
3. **일이 밀리면 알아서 다시 넣게(업무 층)** — 실행기 내장 예약으로 매시 세 업무 진도 점검: 일상 글(시간당 45건 기대), 노출 확인(시간당 300건 기대), 키워드(브랜드별 확정 증가). 기대 미달·정지·실패면 자동 재큐 + 슬랙 🔴, 정상이면 📊 한 줄. 감시 층의 실행 기록이 15분 넘게 없으면 여기서 🔴.
4. **서로 방해하지 않게(자원 층)** — 노출 확인 전용 DB 분리(준비 완료, 오늘 밤 전환), DB 쓰기 재시도 공통 헬퍼, Apps Script 호출 묶음·재시도 통일, CPU 과부하 시 작업자 수 자동 조절.
5. **바꿀 때 망가지지 않게(변경 층)** — 코드·스크립트 변경은 테스트 통과 후 커밋, 실행기 반영은 02:30 창(긴급 제외), 변경 뒤 30분 실측 필수. 매일 02:30 자가 점검 보고에 세 업무의 24시간 가동률(끊긴 시간 합계)을 적는다.

## 오늘 순서
1. 감시 통합(V2R-Supervisor) 구현·등록 — 오후.
2. 노출 작업자·채우기 순환 상주형 — 진행 중(오후 완료).
3. 매시 진도 점검 3종 — 일상 글은 완료(재시작 시 활성), 노출·키워드 추가 — 오후.
4. DB 분리 전환 — 오늘 밤 02:30 창.
5. 내일 02:30 첫 가동률 보고.
