사용자 지시: "Make 클로드 모든 모듈에 user text 지침과 system 프롬프트 지침이 혼재. **모든 지침을 다 가져가되 역할에 맞게 구분**하고, **중복·강조 남발을 깔끔하게 정리**. 정리본은 Make에도 그대로 반영할 예정."

## 입력
`warehouse/guides/★NEW 카페 바이럴★/<브랜드> … (claude).md` — 시나리오별로 Claude 모듈 1(본문), 모듈 2(댓글)마다 `### 시스템 프롬프트`, `### 사용자 프롬프트`가 있다. 팥순이는 질문형·후기형 파일 2개. 우아덤은 `우아덤 카페 단순화`가 본편, `카페 바이럴 자동화(우아덤)`는 옛 판(차이만 참고).

## 변경 로그

- 합침(중복): 같은 규칙이 N번 → 1번. 원문 인용 짧게.

- 삭제 없음 확인: 원본의 규칙 항목 수 → 정리본 항목 수, 빠진 규칙 0개.

## 역할 구분 원칙
- **시스템 프롬프트** = 실행마다 바뀌지 않는 것 전부: 역할/페르소나 지시, 형식(출력 형식, 줄 나눔, 글자 수, 문단), 스타일(AI 티 제거, 맞춤법 규칙), 브랜드 사실(제품명·표기·권위재·원리·금칙어), 댓글 구조·역할·순서·브랜드 등장 시점, 예시(예시라는 표시와 "베끼지 말 것" 포함).
- **사용자 프롬프트** = 실행마다 바뀌는 입력만: 키워드(`{{42.`0`}}` 등 Make 변수 **그대로**), 조사 결과(`{{74.choices[].message.content}}`), 본문(모듈 2에서 모듈 1 결과), 시트 열 값, 그리고 "위 시스템 규칙대로 작성" 한 줄. 지침 문장은 사용자 프롬프트에 남기지 않는다(변수 설명 한 줄은 허용).
- Make 변수 표기(`{{…}}`)와 자리표시자(`{키워드}`, `{B/A}`, `{}`)는 글자 하나 바꾸지 않는다.

## 정리 원칙
1. **빠뜨리지 않는다.** 규칙·예시·금칙어·수치는 전부 살린다. 표현만 다듬는다.
2. 같은 규칙이 여러 번 → 한 번, 가장 구체적인 문장으로. 부분적으로 다른 반복은 합쳐서 한 항목.
3. 강조 기호(★, (중요), (무조건), 느낌표 반복, 같은 문장 두 번)는 제거하고, 대신 "절대 규칙" 절에 모아 번호를 붙인다. 강조가 의미 있는 우선순위였다면 그 절에 반영.
4. 순서: 역할 → 절대 규칙 → 형식 → 내용 규칙 → 브랜드 정보 → 댓글 구조(모듈 2) → 예시 → 금지 목록.
5. 원문 말투(반말 지시)는 통일해서 유지. 새 규칙을 만들어 넣지 않는다.
6. 충돌은 임의로 고르지 말고 로그에 남긴다(둘 다 적고 "사용자 결정 필요"). 단 명백한 오타·중복 값은 정리.
7. 정리본 프롬프트는 Make 텍스트 상자에 그대로 붙일 수 있게 순수 텍스트(마크다운 헤더 없이, 번호·대시만).
